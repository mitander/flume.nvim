SETUP                                                              *flume-setup*

Configure and apply one palette with a single setup call:
>
    require("flume").setup({ schema = "dusk" })
<

Do not follow setup() with :colorscheme. When no Lua options are needed, a
colorscheme command is the alternative:
>
    colorscheme flume-dusk
<

Flume targets Neovim 0.9+ and expects 'termguicolors'.

==============================================================================
PALETTES                                                        *flume-palettes*

Canonical schema IDs:

    dusk    dark   original quiet violet Flume
    opal    light  vivid inks on cool opalescent paper
    mira    dark   technical plum with cyan, teal, and magenta
    mesa    light  warm rose-mineral paper

Canonical colorscheme entry points are "flume-dusk", "flume-opal",
"flume-mira", and "flume-mesa".

==============================================================================
OPTIONS                                                          *flume-options*

Defaults:
>
    require("flume").setup({
        schema = "dusk",
        transparent = false,
        terminal_colors = true,
        overrides = {},
        highlights = {},
        styles = {
            comments = {}, functions = {}, keywords = {}, strings = {},
            types = {}, variables = {},
        },
    })
<

schema ~
    Selects "dusk", "opal", "mira", or "mesa".

transparent ~
    Removes primary editor and sign-column backgrounds. Raised surfaces,
    selections, diffs, and diagnostic backgrounds remain visible.

terminal_colors ~
    Sets g:terminal_color_0 through g:terminal_color_15 from the palette.

overrides ~
    Changes colors by semantic role. Generated extras continue to use canonical
    palettes; runtime saturation transforms are intentionally absent.
>
    require("flume").setup({
        schema = "opal",
        overrides = {
            syntax_comment = "#7a747a",
            syntax_namespace = "#f48a94",
        },
    })
<

styles ~
    Adds broad text attributes to syntax roles.
>
    require("flume").setup({ styles = { comments = { italic = true } } })
<

highlights ~
    Changes an exact, case-sensitive group or Tree-sitter capture. Values may
    be tables or functions receiving the resolved palette colors.

SYSTEM APPEARANCE ~
    Flume does not install an OS watcher. Call setup() from an existing
    appearance hook after that hook updates 'background':
>
    require("flume").setup({
        schema = vim.o.background == "light" and "opal" or "dusk",
    })
<

==============================================================================
COMMANDS                                                        *flume-commands*

:FlumeReload                                                      *:FlumeReload*
    Reload the editor-local palette and notify ColorScheme integrations.

:FlumeCompile                                                    *:FlumeCompile*
    Regenerate forty canonical files without changing the active palette.

:FlumeSync [schema]                                                 *:FlumeSync*
    Apply a canonical palette and activate supported live integrations.

:FlumeInstallExtras [app]                                  *:FlumeInstallExtras*
    Symlink generated extras into safe standard locations. Supported app
    arguments: ghostty, kitty, opencode, tmux, lsd.

:FlumeExtras                                                      *:FlumeExtras*
    Open refusal-safe copy/link instructions for extras.

:checkhealth flume                                           *flume-checkhealth*
    Check the selected palette and all ten generated files.

==============================================================================
EXTRAS                                                            *flume-extras*

Every canonical artifact includes its palette suffix. The active set is
atomically linked under extras/current/ and records its canonical schema in
extras/current/schema.

    APP       DUSK ARTIFACT
    Ghostty   extras/ghostty/flume-dusk
    Kitty     extras/kitty/flume-dusk.conf
    Tmux      extras/tmux/colors-dusk.conf
    LSD       extras/lsd/colors-dusk.yaml
    OpenCode  extras/opencode/flume-dusk.json
    Lazygit   extras/lazygit/flume-dusk.yml
    fzf       extras/fzf/flume-dusk.opts
    Delta     extras/delta/flume-dusk.gitconfig
    Pi        extras/pi/flume-dusk.json
    Tuxedo    extras/tuxedo/flume-dusk.toml

Only Ghostty, Kitty, OpenCode, Tmux, and LSD have safe installer destinations.
The other tools support multiple include locations, so Flume does not guess.

==============================================================================
HIGHLIGHTS                                                    *flume-highlights*

Built-in surfaces include Neovim UI, diagnostics, Tree-sitter, LSP semantic
tokens, GitSigns, Oil, Telescope, nvim-cmp, lazy.nvim, WhichKey, Mason, Trouble,
Neo-tree, nvim-tree, Snacks, and fzf-lua.

Use :Inspect or :highlight GroupName and the `highlights` option for exact
changes. See docs/color-system.md for the semantic schema contract.

*flume.txt*	Four palettes for Neovim and matching developer-tool themes
*flume.nvim* *flume*

Flume keeps ordinary identifiers neutral and uses color for syntax and state.

SETUP                                                            *flume-setup*

Install mitander/flume.nvim with your plugin manager. Requires Neovim 0.9+
with a true-color terminal. Once the plugin is on 'runtimepath':
>
    vim.opt.termguicolors = true
    require("flume").setup({ schema = "dusk" })
<
The editor now uses Dusk. :echo g:colors_name should print flume-dusk.
setup() configures and applies the theme; no :colorscheme call is needed.
Each setup() starts from defaults, so include all your options in one call.

If you do not need Lua options, use this alternative in init.vim:
>
    set termguicolors
    colorscheme flume-dusk
<
Tree-sitter parsers and language servers are optional. Flume supplies colors
but does not install or configure those providers.

==============================================================================
PALETTES                                                      *flume-palettes*

Schema  Appearance  Character ~
    dusk    dark    quiet violet
    opal    light   purple, red, and sea-glass on cool porcelain
    mira    dark    Dusk-derived pastels on neutral graphite
    mesa    light   restrained mineral inks on soft rose-gray paper

The colorscheme names are flume-dusk, flume-opal, flume-mira, and flume-mesa.
Each palette sets 'background' to its appearance.

==============================================================================
EVERYDAY USE                                                     *flume-usage*

Try another palette without changing shared external themes:
>
    :colorscheme flume-opal
<
This keeps the configured styles and overrides. Change `schema` in your setup
for the next startup. To change the shared theme as well, use |:FlumeSync|.
See |flume-watch_sync| for how other editors follow that choice.

For italic comments and a custom current line number, replace your setup with:
>
    require("flume").setup({
        schema = "opal",
        styles = { comments = { italic = true } },
        highlights = {
            CursorLineNr = { bold = true, fg = "#413b49" },
        },
    })
<
Use :set cursorline number to see the line-number change. Use |:Inspect| on
syntax or :highlight GroupName on UI groups to choose an exact override.

==============================================================================
OPTIONS                                                        *flume-options*

Defaults:
>
    require("flume").setup({
        schema = "dusk",
        transparent = false,
        terminal_colors = true,
        watch_sync = true,
        follow_sync = false,
        dev = false,
        overrides = {},
        schema_overrides = {},
        highlights = {},
        styles = {
            comments = {}, functions = {}, keywords = {}, strings = {},
            types = {}, variables = {},
        },
    })
<

schema ~                                                        *flume-schema*
    Selects one of the IDs in |flume-palettes|.

transparent ~                                              *flume-transparent*
    Removes primary editor and sign-column backgrounds. Raised surfaces,
    selections, diffs, and diagnostic backgrounds remain visible. Contrast
    depends on your terminal background when transparency is enabled.

terminal_colors ~                                      *flume-terminal_colors*
    Sets g:terminal_color_0 through g:terminal_color_15 for Neovim's terminal.
    When false, clears those variables. This does not theme the host terminal;
    use |flume-extras| for that.

watch_sync ~                                                *flume-watch_sync*
    Applies palettes synchronized by other editors sharing the data directory.
    Enabled by default. Set to false to ignore switches while the editor runs.
    Selecting a non-Flume colorscheme stops watching. Call setup() to resume.

follow_sync ~                                              *flume-follow_sync*
    At setup, prefers the validated shared schema over the configured schema.
    Missing or invalid state uses the configured fallback. Defaults to false.
>
    require("flume").setup({ schema = "mesa", follow_sync = true })
<
    After :FlumeSync mira, startup selects Mira; Mesa remains the fallback.
    Setup does not rewrite your Lua configuration or the shared marker.
    Reload preserves the editor's current palette instead of rereading state.
    Set both follow_sync and watch_sync to false for an independent editor.
    See |flume-data| for the directory and accessors.

dev ~                                                              *flume-dev*
    Reloads Flume when Lua files in the checkout's lua/ directory are saved.
    Includes language modules and the lualine theme. Save-time reload preserves
    the current schema and options, without synchronizing extras or replacing
    another theme. With dev enabled, |:FlumeSync| also reloads source and
    regenerates canonical extras before synchronizing. No separate compile is
    needed. A failed reload restores the previous modules and theme. Failed
    reload or compilation stops sync before publication and app reload requests.
    Fix the source and retry. See docs/DEVELOPMENT.md for development commands.

overrides ~                                                  *flume-overrides*
    Changes palette colors by role before highlights are built. Exact roles
    and default values are listed in docs/palette-manifest.md.
>
    require("flume").setup({
        schema = "opal",
        overrides = { syntax_comment = "#7a747a" },
    })
<
    Global overrides apply to every palette. Use |flume-schema_overrides| for
    palette-specific changes. Exact |flume-highlights| overrides apply last.
    External themes use the palette's default colors, not editor overrides.
    Check contrast against your rendered background after customization.

schema_overrides ~                                    *flume-schema_overrides*
    Palette-role overrides keyed by schema. Each load resolves canonical colors,
    then global `overrides`, then the selected schema's overrides. Switching
    palettes or reloading selects the corresponding table automatically.
>
    require("flume").setup({
        schema_overrides = {
            opal = { syntax_function = "#345678" },
        },
    })
<
    This changes Opal only. Other palettes keep their canonical colors and any
    global overrides. Generated external themes retain their canonical colors.

styles ~                                                        *flume-styles*
    Adds text attributes to the syntax families shown in the defaults above.
    Values use |nvim_set_hl()| attributes, for example { italic = true }.

highlights ~                                         *flume-highlights-option*
    Replaces an exact, case-sensitive group or Tree-sitter capture after other
    highlights are built. Values are |nvim_set_hl()| tables or functions that
    receive resolved palette colors. Functions can follow palette changes:
>
    require("flume").setup({
        highlights = {
            CursorLineNr = function(c)
                return { fg = c.accent, bold = true }
            end,
        },
    })
<

SYSTEM APPEARANCE ~                                         *flume-appearance*
    Flume does not watch OS appearance. Call setup() from your appearance hook
    after that hook updates 'background':
>
    require("flume").setup({
        schema = vim.o.background == "light" and "opal" or "dusk",
    })
<
    Include your other options in that call too.

==============================================================================
COMMANDS                                                      *flume-commands*

Commands become available when Flume is loaded.

:FlumeTweak [schema]                              *:FlumeTweak* *flume-tweak*
    Open an isolated role-color preview in a scratch tab. h/l cycle shade
    candidates, c chooses another palette ink, Enter accepts #RRGGBB, and r
    resets a role. p/P switch palettes and s/S switch realistic language samples.
    y copies edited schema_overrides to the unnamed register. q or Escape closes
    and discards the draft. No global palette, config or shared theme is changed.

    The preview uses actual installed Tree-sitter captures or explicitly labelled
    plain text. It does not source global Vim syntax definitions. It uses opaque surfaces and bypasses exact
    highlight overrides. Diagnostic examples and labelled UI swatches are not
    language-server output or live menus. No parser or server is installed.
    Changing colorscheme or reloading Flume closes it. See docs/tweak.md.

:FlumeReload                                                    *:FlumeReload*
    Reload source modules and the editor-local palette. Preserves options and
    notifies ColorScheme integrations without synchronizing external themes.

:FlumeCompile                                                  *:FlumeCompile*
    Regenerate integration files from the palettes in the checkout. Does not
    change the active palette. Use after changing palette or exporter code.

:FlumeSync [schema]                                               *:FlumeSync*
    Apply a palette and activate its shared integration set. With no argument,
    use the editor's current palette. |flume-watch_sync| editors follow it.
    With |flume-dev| enabled, reload source and regenerate extras first. With
    dev disabled (the default), use bundled artifacts without compilation or
    source reload. Plugin-manager version pins select the installed release.
    Reports reload requests separately from file synchronization. External apps
    may still need restarting. See |flume-extras| for per-app behavior.

:FlumeInstallExtras [app]                                *:FlumeInstallExtras*
    Link an external theme at a standard destination. With no argument, link
    all supported install destinations, with separate Fish consent prompts.
    See |flume-install-extras| before running it.

:FlumeExtras                                                    *:FlumeExtras*
    Open a scratch buffer with the current paths and shell link instructions
    for supported install destinations. Shell instructions refuse existing paths.

:checkhealth flume                                         *flume-checkhealth*
    Check Neovim, 'termguicolors', palette, shared state, installer links, and
    generated files. Unlinked apps may be unused or configured manually.

INSTALL AND SELECT                                      *flume-install-extras*

For example, install the Ghostty theme from Neovim:
>
    :FlumeInstallExtras ghostty
<
Then add `theme = flume` to your Ghostty config and reload it. Installing the
file alone does not select the theme. Switch the shared palette with:
>
    :FlumeSync mira
<
The installer creates the active set if needed. Supported app arguments and
symlink destinations:

    ghostty   ~/.config/ghostty/themes/flume
    kitty     ~/.config/kitty/themes/flume.conf
    opencode  ~/.config/opencode/themes/flume.json
    tmux      ~/.tmux/flume-theme.conf
    lsd       ~/.config/lsd/colors.yaml
    lazygit   ~/.config/lazygit/flume.yml
    fish      ~/.config/fish/conf.d/flume.fish (or $XDG_CONFIG_HOME/fish/conf.d/)
    fish_tools ~/.config/fish/conf.d/flume-tools.fish (same XDG rule)
    pi        ~/.pi/agent/themes/flume.json

It refuses existing regular files and directories, but replaces existing
symlinks. Check the destination first if you already manage a theme there.
Move an existing file aside only after preserving any personal settings.
For Lazygit, export `LG_CONFIG_FILE` with your personal config first and
`~/.config/lazygit/flume.yml` second so the active fragment is layered.

For LSD filename colors, |:FlumeExtras| prints Fish and Bash/Zsh commands that
set world-writable directory names to magenta on the normal background via
LS_COLORS. The YAML theme alone only styles metadata.

For Fish, the installer asks Yes/No before linking the auto-loaded conf.d
fragment. No prints a manual source snippet with the active path. Cancel makes
no changes. It never edits config.fish. The no-argument installer also prompts
for Fish. conf.d runs before config.fish, so later color settings can override
Flume. For manual setup, source <data-dir>/current/fish.fish after other color
settings in your Fish config.fish instead.

The Fish fragment colors command-line syntax and the completion pager without
changing your prompt or writing universal variables. Source it again in existing
shells after synchronization. New shells apply it at startup.

Optional Fish 3.5+ tool setup:
>
    :FlumeInstallExtras fish_tools
<
Choose Install to link conf.d/flume-tools.fish. Do not install or cancel makes
no changes. The helper configures fzf's active options file, Lazygit's layered
config and the non-sticky world-writable-directory LS_COLORS rule.

After installation, two quoted source commands are printed. The first preserves
exports for already configured tools. The second adds --adopt to replace this
session's FZF_DEFAULT_OPTS_FILE and LG_CONFIG_FILE exports instead. Run the
command you want in Fish. Both update the LS_COLORS directory rule. Linking
alone does not change an existing shell. Neovim cannot change its parent shell's
environment. No variable clearing or shell restart is needed.

Normal startup respects explicit tool exports. --adopt is a one-time source
argument, not a saved preference. It does not modify persistent
universal variables. Later config.fish settings can override the defaults.
Reinstalling refreshes a stale tool fragment while retaining the shared palette.
Lazygit owns config-directory discovery. Repeated sourcing does not grow
LS_COLORS. This does not change macOS BSD ls or prompts.

Pi can be linked with :FlumeInstallExtras pi, then selected in Pi's settings.
Installation reports the destination and next setup step, not application
readiness. For examples and manual recipes, see docs/workflows.md. Other tools
have no automatic installer because their include locations vary.

TMUX COLORS ~

The Tmux fragment supplies variables, not a statusline layout. Source it before
consumer styles. thm_bg and thm_fg are the canvas and primary text. Use
thm_surface for raised UI backgrounds, thm_muted for readable secondary text,
and thm_on_accent for text on filled accent/state colors. For example: >
    set -g message-style "bg=#{thm_surface},fg=#{thm_fg}"
    set -g message-command-style "bg=#{thm_surface},fg=#{thm_accent}"
    set -g window-status-style "bg=#{thm_bg},fg=#{thm_muted}"
    set -g window-status-current-style "bg=#{thm_accent},fg=#{thm_on_accent}"
<
Existing variable meanings are unchanged. thm_black and thm_gray are ANSI black,
not UI surfaces. thm_lgray is decorative placeholder ink, not readable labels.
message-command-style applies to vi command mode, not prompt insertion mode.
The consumer owns the actual pairs, layout and reload behavior.

RELOAD BEHAVIOR ~

:FlumeSync requests Ghostty reloads through AppleScript on macOS, or SIGUSR2
on Linux when pkill is available. It sources ~/.tmux.conf when inside Tmux and
notifies a linked ~/.pi/agent/themes/flume.json theme. Sync prints one success
line, with manual reload hints only for installed adapter links that could not
be refreshed. Apps must already select or include Flume. A reload request is
not proof that the application applied it.
Other apps need their own reload action or a new invocation; publishing an
active set does not make them reload.

SHARED DATA                                                       *flume-data*

Active sets live in stdpath("data")/flume, outside the checkout. Editors using
the same directory share the palette. Print the exact path:
>
    :lua print(require("flume").get_sync_dir())
<
Set FLUME_DATA_DIR before startup to use another shared directory.
get_active_schema() returns the validated shared schema, or nil when absent.
For custom consumers, current/palette.json contains the default palette colors.
Its format and atomic-switch contract are in docs/semantic-export.md.

After upgrading from checkout-owned state, run :FlumeSync and
:FlumeInstallExtras, then update manual includes to <data-dir>/current/.
Recognized legacy checkout links are forwarded when writable, but direct data
links survive plugin replacement. Migration details: docs/semantic-export.md.

HIGHLIGHTS                                                  *flume-highlights*

Flume defines Neovim UI, diagnostics, Tree-sitter, and LSP semantic groups.
Plugin highlights cover GitSigns, Oil, Telescope, nvim-cmp, lazy.nvim,
WhichKey, Mason, Trouble, Neo-tree, nvim-tree, Snacks, and fzf-lua. These
plugins are not dependencies. BlinkCmpGhostText is also defined.

LUALINE ~                                                      *flume-lualine*

Select Flume in your existing lualine setup:
>
    require("lualine").setup({
        options = { theme = "flume" },
        -- Keep your own sections and component options here.
    })
<
Lualine reloads named themes on ColorScheme; no extra callback is needed.
A precomputed theme or component color table can retain old colors. Use
component color functions when colors must follow palette changes.

==============================================================================
TROUBLESHOOTING                                        *flume-troubleshooting*

Theme did not load ~
    Check :echo g:colors_name. If it is not a Flume name, confirm the plugin
    loads before setup() and no later configuration selects another theme.
    With lazy.nvim, use the eager loading specification in README.md.

Colors differ from the previews ~
    Check :set termguicolors? and your terminal's true-color support. Previews
    use opaque backgrounds and Tree-sitter; transparency, terminal opacity,
    parsers, and language servers can change what you see. Inspect syntax with
    |:Inspect| and UI groups with :highlight GroupName.

Palette changes unexpectedly or resets at startup ~
    Running-editor and startup selection are separate. See |flume-watch_sync|
    and |flume-follow_sync|. To isolate an editor, disable both options.

External app stays on the old palette ~
    Check the selected theme/include, then the link reported by
    :checkhealth flume. Use the stable current/ path, not a resolved set path.
    Reload the app or start a new invocation as described in |flume-extras|.
    Local `overrides` do not alter external themes; see |flume-overrides|.

Installer refuses a path ~
    Preserve your existing file and inspect the destination before relinking.
    See |flume-install-extras|. For legacy forwarding warnings or a stale
    lock, follow the migration procedure in docs/semantic-export.md.

Help is unavailable ~
    Confirm the plugin is on 'runtimepath'. Run :helptags ALL to rebuild tags.
